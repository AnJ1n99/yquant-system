# 队列测试

仅在 Linux 上使用 clang++-19 构建：

```sh
./scripts/benchmark.sh
# 也可透传 GoogleTest 参数，只运行性能测试：
./scripts/benchmark.sh --gtest_filter='*Benchmark*'
```

脚本自动切换到仓库根目录，使用 `build/bench` 配置和编译。每次创建独立的 `build/bench/logs/run-时间-随机后缀.log`，同时显示终端输出。日志包括配置与编译报错、测试通过／失败／跳过状态、每轮原始成绩、汇总、Git 提交及脏状态、源码和可执行文件 SHA-256、编译器版本、CPU 数量及退出码。`build/` 已被 Git 忽略，不提交这些日志。跨机器对比前请自行保存日志；不要把构建目录作为长期归档。

若构建或测试失败，脚本返回非零，不会因 `tee` 成功而误报成功。可执行文件直接运行仍只写终端；需要自动保存日志时使用上述脚本。每轮成绩在全部计时完成后按原始顺序输出，不把日志写入队列热循环。

脚本回归检查（使用替身工具，不运行性能测试）：

```sh
bash benchmark/test_runner.sh
```

每项测试有 120 秒进程级截止时间，超时打印当前测试及错误并以 124 退出。多数正确性测试不要求绑核。背压测试与两项性能测试从允许的 CPU 集合中选择两个 CPU，集合不足或绑核失败时跳过，结束后恢复调用线程原来的集合。

每轮使用同一队列先传输 100,000 条消息预热，双方同步后开始正式测量。吞吐时间从生产者释放同步点之前到消费者读完最后一条消息为止，包含一次起始同步开销，不包含线程启动和回收。乒乓计时起止都在请求线程，消息校验在循环内累计，线程回收后才断言，避免数据错误导致进程异常析构。

吞吐以完整消费的消息数计数；RTT 输出是七轮平均值的最小、中位和最大值，不是逐消息分位数。固定条数预热不保证 CPU 频率稳定。2 vCPU KVM 环境只能观察吞吐方向及往返时间，不能据此声称可靠提升倍数或物理核拓扑收益。

背压测试用 1024 个槽位传输 20,000,000 条，生产者与消费者分别绑到两个 CPU，容量远小于总量，生产者必然反复阻塞在满队列上。它同时断言阻塞次数大于零：若队列始终未满，说明本次运行没有压到边界，直接判失败，避免把"没压到"当成通过。

验收：正确性测试全部通过；单 CPU 或绑核失败时背压测试与性能测试明确跳过；无效 CPU 返回失败；超时以 124 退出；损坏乒乓消息报告测试失败而非 SIGABRT；背压场景不丢消息、不读错位且确实发生过阻塞；两项基准完成且计时为正。
